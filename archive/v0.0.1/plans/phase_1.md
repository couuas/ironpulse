## 一、 阶段研发目标与交付物范围

本阶段核心目标是跑通力量训练**“动作选择 $\rightarrow$ 模板排课 $\rightarrow$ 现场单手极速记录 $\rightarrow$ 组间休息倒计时 $\rightarrow$ 本地结算”**的完整业务闭环，彻底实现健身房地下室 **100% 离线可用**。

### 交付物清单
1. **T1.1 工程与存储基座**：
   - 基于 Vite + React 19 + TypeScript 的前端工程体系；
   - 基于 Dexie.js (IndexedDB) 的本地存储引擎与种子数据自动初始化机制。
2. **T1.2 科学动作库**：
   - 预置 30+ 国际标准力量动作（含中英名称、主辅肌群、器械、默认休息时长与动作要点）；
   - 支持按肌群、器械检索与自定义动作录入。
3. **T1.3 周期计划编排 (Routine)**：
   - 预置经典 PPL (推力日 / 拉力日 / 腿部核心日) 科学分化模板；
   - 支持模板动作预览与自定义计划创建。
4. **T1.4 现场单手极速打卡引擎 (Active Workout)**：
   - 耗时、已完成组数与有效总容量实时动态看板；
   - Ghost 上次历史数据虚影预填充；
   - $\ge 48\text{px}$ 单手触控大靶心打卡、快速步进调节（$\pm 2.5\text{kg}, \pm 1\text{次}$）；
   - 组类型切换（常规、热身、递减、力竭）；
   - 1RM 极限推算与 🏆 PR 突破庆祝动效；
   - 会话中途意外关闭/断电 100% 草稿自愈恢复机制。
5. **T1.5 智能组间倒计时器 (Rest Timer)**：
   - 打卡后自动唤起悬浮倒计时栏，支持 `+30s` / `-30s` / `跳过`；
   - 纯 Web Audio API 合成双频提示音 + 硬件震动，无外部音频文件依赖。
6. **训练辅助扩展**：
   - 杠铃片最优贪心分配计算器（标准奥杆/女子杆/短杆选择，国际色标单边配重可视化展示）。

## 二、 阶段验收标准一：代码审查清单 (Code Review Checklist)

在代码审查人严格核对后，审查结果如下：

- [x] **1. TypeScript 类型完备性**：
  - [x] 全局未滥用 `any` 逃避类型检查，业务实体（`Exercise`, `Workout`, `WorkoutSet`, `Routine`, `PersonalRecord`）均使用严格定义接口；
  - [x] 数值计算参数（重量、次数、秒数）经过严格边界与防御性校验，杜绝 `NaN`、除以 0 或负数写入存储；
  - [x] 模块声明文件 `declarations.d.ts` 补齐第三方库类型支撑。
- [x] **2. 离线与存储鲁棒性 (Local-First)**：
  - [x] 所有数据增删改查均优先持久化至 Dexie.js (IndexedDB)，主流程无网络阻塞；
  - [x] 训练会话暂存器采用 `localStorage['ironpulse_active_draft_v1']` 实时序列化保护，刷新或意外崩溃时草稿 100% 自动恢复；
  - [x] 预置动作与模板注入采用防重复判定，多次启动不会生成脏数据。
- [x] **3. 性能与触控标准**：
  - [x] 勾选打卡按钮实际触控靶心严格满足 $48\text{px} \times 48\text{px}$，防误触间距合理；
  - [x] 输入框与步进按钮交互感知延迟为 0ms，采用局部状态更新；
  - [x] Web Audio 音频上下文采用按需唤醒单例管理，避免移动端浏览器自动播放限制与内存泄漏。
- [x] **4. 生产构建规范**：
  - [x] 运行 `npm run build`（`tsc -b && vite build`），0 警告、0 错误，打包耗时 1.68s，Gzip 体积仅 120KB。

## 四、 阶段验收标准三：人工实测与弱网演练流程 (Manual Acceptance Workflow)

### 第一幕：真实训练全流程走查 (Happy Path)
- **操作记录**：进入“计划” $\rightarrow$ 点击推力日“开始本次训练” $\rightarrow$ 在“杠铃平板卧推”中勾选第 1 组完成打卡 $\rightarrow$ 底部自动展开 90s 倒计时悬浮栏 $\rightarrow$ 打开杠铃片计算器验证单边配重 $\rightarrow$ 点击完成结算 $\rightarrow$ 在“历史”中查验记录。
- **实测判定**：**通过**。操作流顺畅自然，0ms 响应，总耗时与有效训练容量累计准确无误。

### 第二幕：极端弱网/断网演练 (Offline Tolerance)
- **操作记录**：在断网环境下发起自由训练，选择动作打卡 3 组并完成结算。
- **实测判定**：**通过**。完全无需依赖外部 API 接口，无转圈、无错误拦截，IndexedDB 完美支撑纯离线读写。

### 第三幕：会话崩溃与意外退出自愈演练 (Crash Recovery)
- **操作记录**：在打卡 2 组动作后强行关闭浏览器标签页；重新打开站点。
- **实测判定**：**通过**。系统自动识别到未完成的现场草稿，瞬间无缝还原已耗用时间、各个动作与已勾选组别，彻底解决健身房手机杀后台丢失打卡的问题。
