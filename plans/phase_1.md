## 一、 阶段研发目标与交付物范围

本阶段核心目标是跑通力量训练**“动作选择 $\rightarrow$ 模板排课 $\rightarrow$ 现场单手极速记录 $\rightarrow$ 组间休息倒计时 $\rightarrow$ 本地结算”**的完整业务闭环，彻底实现健身房地下室 **100% 离线可用**。

### 交付物清单
1. **T1.1 工程与存储基座**：
   - 基于 Vite + React 19 + TypeScript 的前端工程体系；
   - 基于 Dexie.js (IndexedDB) 的本地存储引擎与种子数据自动初始化机制。
2. **T1.2 科学动作库**：
   - 预置 30+ 国际标准力量动作（含中英名称、主辅肌群、器械、默认休息时长与动作要点）；
   - 支持按肌群、器械检索与自定义动作录入。
3. **T1.3 周期计划编排 (Routine)**：
   - 预置经典 PPL (推力日 / 拉力日 / 腿部核心日) 科学分化模板；
   - 支持模板动作预览与自定义计划创建。
4. **T1.4 现场单手极速打卡引擎 (Active Workout)**：
   - 耗时、已完成组数与有效总容量实时动态看板；
   - Ghost 上次历史数据虚影预填充；
   - $\ge 48\text{px}$ 单手触控大靶心打卡、快速步进调节（$\pm 2.5\text{kg}, \pm 1\text{次}$）；
   - 组类型切换（常规、热身、递减、力竭）；
   - 1RM 极限推算与 🏆 PR 突破庆祝动效；
   - 会话中途意外关闭/断电 100% 草稿自愈恢复机制。
5. **T1.5 智能组间倒计时器 (Rest Timer)**：
   - 打卡后自动唤起悬浮倒计时栏，支持 `+30s` / `-30s` / `跳过`；
   - 纯 Web Audio API 合成双频提示音 + 硬件震动，无外部音频文件依赖。
6. **训练辅助扩展**：
   - 杠铃片最优贪心分配计算器（标准奥杆/女子杆/短杆选择，国际色标单边配重可视化展示）。

## 二、 阶段验收标准一：代码审查清单 (Code Review Checklist)

在代码合并或阶段封包前，审查人必须严格核对以下代码质量指标：

- [ ] **1. TypeScript 类型完备性**：
  - [ ] 全局未滥用 `any` 逃避类型检查，业务实体（`Exercise`, `Workout`, `WorkoutSet`, `Routine`）均使用严格类型；
  - [ ] 数值计算参数（重量、次数、秒数）经过防御性校验，避免 `NaN` 或负数写入存储。
- [ ] **2. 离线与存储鲁棒性 (Local-First)**：
  - [ ] 所有数据操作均优先写入 Dexie.js，无网络请求阻塞主流程；
  - [ ] 训练会话暂存器采用 `localStorage` + `IndexedDB` 双层容灾策略，保证异常退出时草稿无损；
  - [ ] 预置动作库注入采用自增防重机制，不会因多次刷新导致数据重复。
- [ ] **3. 性能与触控标准**：
  - [ ] 勾选完成按钮（✓）触控区域满足 $\ge 48\text{px} \times 48\text{px}$，防误触间距合理；
  - [ ] 输入与步进操作采用本地瞬时响应（0ms 感知延迟），无多余整页重绘；
  - [ ] Web Audio 音频上下文采用按需唤醒单例模式，避免内存泄漏或浏览器音频资源耗尽。
- [ ] **4. 生产构建规范**：
  - [ ] 运行 `npm run build` 输出 0 警告、0 错误；
  - [ ] 打包产物体积精简，CSS 无未使用的大型库冗余。

## 四、 阶段验收标准三：人工实测与弱网演练流程 (Manual Acceptance Workflow)

由产品经理或训练者按照真实健身场景执行如下**三幕实测走查**：

### 第一幕：真实训练全流程走查 (Happy Path)
1. 打开应用，进入“计划” $\rightarrow$ 选择“推力日 (Push Day)” $\rightarrow$ 点击“开始本次训练”；
2. 检查第 1 个动作“杠铃平板卧推”：
   - 点击“配重”，选择目标 70kg，核对单边杠铃片图形（20kg 杆 + 25kg 单边片）；
   - 点击打卡第 1 组，听取提示音，观察底部 90s 倒计时悬浮栏展开；
   - 切换至“动作库”查看其他动作，验证倒计时依然在底部稳定运行且不中断；
3. 完成后续组别打卡，点击“完成结算”，验证总容量（Volume）与打卡总组数统计无误。

### 第二幕：极端弱网/断网演练 (Offline Tolerance)
1. 在浏览器 DevTools 的 Network 面板中勾选 **`Offline` (完全离线)** 或手机开启飞行模式；
2. 发起一次新的自由训练，添加动作并勾选打卡 3 组；
3. **关键判定**：
   - 页面不得出现任何由于请求失败导致的白屏、接口红色报错拦截或保存死锁；
   - 100% 本地记录，结算正常保存至 IndexedDB。

### 第二幕：会话崩溃与意外退出自愈演练 (Crash Recovery)
1. 启动一场训练，记录 2 个动作共 5 组数据，其中已勾选完成 3 组；
2. 在训练中途**直接强行关闭当前浏览器标签页或强杀进程**；
3. 重新打开站点：
   - **关键判定**：系统自动恢复训练中状态，无需任何手动找回操作；已耗费时长、已录入的重量次数以及已勾选完成的组别**100% 完整保持**。
