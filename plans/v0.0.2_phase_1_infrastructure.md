# 📌 IronPulse v0.0.2 - Phase 1 (基础设施、后端搭建与部署适配) 研发实施计划

| 计划版本 | 关联阶段 | 交付周期 | 验收模式 |
| :--- | :--- | :--- | :--- |

---

## 一、 阶段研发目标

本阶段旨在为 v0.0.2 的云端协同系统铺设底层基础设施。重点包括：
1. 在前端根目录新增部署配置以支持现代静态托管平台。
2. 在项目中搭建出完全独立的 Node.js 后端服务骨架。
3. 提供 Docker 化的一键自建部署方案。

## 二、 交付物与任务清单

### T1.1 前端持续集成 (CI/CD) 适配
- [ ] 编写 `vercel.json` 补充 `rewrites` 规则，将所有的请求 fallback 到 `/index.html`，解决前端 SPA 在 Vercel 上的直接访问 404 问题。
- [ ] 确保前端 `package.json` 中的 `build` 命令无隐式报错，且 Vite 产物（dist）结构清晰。

### T1.2 后端服务初始化 (`server/` 目录)
- [ ] 在仓库根目录建立 `server/` 目录。
- [ ] 初始化 `package.json` 并引入 TypeScript 体系 (`express`, `sqlite3`, `jsonwebtoken` 等依赖)。
- [ ] 配置 `tsconfig.json` 用于后端代码编译。
- [ ] 配置 `eslint` 与 `prettier`，保持与前端一致的代码风格。

### T1.3 核心中间件与数据库连接
- [ ] 实现基础架构代码目录：`server/src/db`, `server/src/routes`, `server/src/middleware`。
- [ ] 编写 `db.ts` 建立与 SQLite 的持久化连接，确保多线程并发读写时的锁处理。
- [ ] 编写 `init_schema.sql`，执行建表语句（用户表及带有同步标记的实体表）。
- [ ] 实现 JWT 鉴权中间件 `authMiddleware.ts`，解析 Token 并在 request 中注入 `userId`。

### T1.4 身份认证路由 (`Auth API`)
- [ ] `POST /api/auth/register`: 接收用户名密码，Bcrypt 散列存储。
- [ ] `POST /api/auth/login`: 校验凭证并签发长期有效的 JWT Token。

### T1.5 极客自建容器化 (Docker Support)
- [ ] 编写 `server/Dockerfile` (基于轻量级的 Node Alpine 镜像)。
- [ ] 编写 `server/docker-compose.yml`，定义端口映射，并将 SQLite 数据目录挂载为外部 volume (`./data:/app/data`) 以持久化用户数据。

## 三、 验收标准

- **架构标准**：前后端解耦明确。后端不包含任何视图引擎（如 EJS），仅作为 Pure API Server 提供 JSON 响应。
- **本地启动验证**：进入 `server` 目录，执行 `npm run dev` 可成功启动服务并在本地 3001 端口监听到请求，无编译报错。
- **容器验证**：执行 `docker compose up --build` 能够瞬间拉起后端服务并持久化生成 `data/ironpulse.sqlite` 文件。
- **Postman 测试**：能成功通过接口注册测试账号、登录并获取合法的 JWT 令牌。
